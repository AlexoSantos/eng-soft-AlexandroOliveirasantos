# 📖 Histórias de Usuário (User Stories)

As Histórias de Usuário são uma ferramenta fundamental no desenvolvimento ágil para humanizar os requisitos de software. Em vez de documentos de especificação densos e estáticos, elas funcionam como um **lembrete para uma conversa** contínua entre o time de desenvolvimento e os stakeholders.

## 🎯 O Objetivo
O foco principal não é apenas documentar o que deve ser feito, mas garantir que o time entenda o **valor de negócio** e o **problema do usuário** antes de qualquer linha de código ser escrita.

---

## 🛠️ A Estrutura (Os 3 Ws)

Uma história de usuário bem escrita geralmente segue o formato:

> **Como** `[Quem - Persona]`
> **Eu quero** `[O quê - Ação/Funcionalidade]`
> **Para que** `[Por quê - Benefício/Valor]`



### Exemplo:
* **Como** um cliente recorrente,
* **Eu quero** salvar os dados do meu cartão de crédito com segurança,
* **Para que** eu possa finalizar minhas compras futuras com apenas um clique.

---

## 💎 Os 3 Cs das User Stories

Para garantir que a história cumpra seu papel, Ron Jeffries definiu o modelo dos 3 Cs:

1.  **Cartão (Card):** A história deve ser curta o suficiente para caber em um post-it ou pequeno card, servindo como uma nota física ou digital da necessidade.
2.  **Conversa (Conversation):** O detalhamento não ocorre no texto, mas na troca de ideias entre o Product Owner, Designer e Desenvolvedores.
3.  **Confirmação (Confirmation):** São os **Critérios de Aceite**. Eles definem o que precisa ser testado para que a história seja considerada "Pronta".

---

## ✅ Critérios de Qualidade (INVEST)

Uma boa História de Usuário deve seguir o acrônimo **INVEST**:

| Letra | Significado | Descrição |
| :--- | :--- | :--- |
| **I** | Independente | Deve poder ser desenvolvida e entregue sem depender de outras. |
| **N** | Negociável | O "como" fazer está aberto a discussão e sugestões do time. |
| **V** | Valiosa | Deve entregar um valor claro para o cliente ou para o negócio. |
| **E** | Estimável | O time deve ter contexto suficiente para estimar o esforço. |
| **S** | Small (Pequena) | Deve caber dentro de uma iteração (Sprint). |
| **T** | Testável | Deve ser possível validar se ela foi concluída com sucesso. |

---

## 🚀 Conclusão

User Stories removem a barreira da "especificação perfeita" e colocam o foco onde ele realmente importa: na **empatia pelo usuário** e na **entrega de valor**. Lembre-se: se não houver conversa, não é uma história de usuário; é apenas um requisito disfarçado.
